# Public Suggestion Box - Backend\n\nThis is the backend server for the Public Suggestion Box application. It manages suggestions, handles administrator authentication, and provides API endpoints for the frontend.\n\nBuilt with Node.js, Express.js, and uses Supabase (PostgreSQL) for the database.\n\n## Features\n\n-   Submit new suggestions.\n-   View publicly approved suggestions.\n-   Admin panel to view all, approve, and delete suggestions.\n-   JWT-based authentication for admin actions.\n\n## Project Structure\n\n```\n/\n├── src/\n│   ├── controllers/    # Request handlers\n│   ├── middleware/     # Custom middleware (e.g., auth)\n│   ├── routes/         # API route definitions\n│   ├── config/         # Configuration files (e.g., database)\n│   ├── utils/          # Utility functions (e.g., logger, errorHandler)\n│   ├── server.js       # Express app setup and middleware\n├── .env.example        # Example environment variables file\n├── .gitignore          # Specifies intentionally untracked files that Git should ignore\n├── index.js            # Entry point of the application\n├── package.json        # Project metadata and dependencies\n└── README.md           # This file\n```\n\n## Prerequisites\n\n-   [Node.js](https://nodejs.org/) (v14.x or later recommended)\n-   [npm](https://www.npmjs.com/) (usually comes with Node.js)\n-   A [Supabase](https://supabase.com/) account and project for the PostgreSQL database.\n\n## Setup\n\n1.  **Clone the repository:**\n    ```bash\n    git clone <your-repository-url>\n    cd <your-project-directory>\n    ```\n\n2.  **Install dependencies:**\n    ```bash\n    npm install\n    ```\n\n3.  **Set up environment variables:**\n    -   Rename `.env.example` (if provided, otherwise create it) to `.env`.\n    -   Open the `.env` file and fill in the required values:\n        ```ini\n        PORT=3001 # Or any port you prefer\n        DATABASE_URL="your_supabase_connection_string_uri"\n        ADMIN_PASSWORD="your_chosen_admin_password" # Choose a strong password\n        JWT_SECRET="your_strong_jwt_secret_key" # A long, random string\n        JWT_EXPIRES_IN="1h" # Or "7d", "30d", etc.\n        FRONTEND_URL="http://localhost:3000" # URL of your frontend app (for CORS during development)\n        # NODE_ENV=development # Optional: set to 'production' when deployed\n        # DEBUG=true # Optional: set to true for verbose debug logs from the logger utility\n        ```\n    -   `DATABASE_URL`: Get this from your Supabase project settings (Database -> Connection string -> URI).\n    -   `ADMIN_PASSWORD`: This password will be used to log in to the admin panel. It's hashed by the application.\n    -   `JWT_SECRET`: A strong, unique secret key used to sign JWTs.\n    -   `FRONTEND_URL`: The URL where your frontend application is running. This is crucial for CORS.\n\n4.  **Set up the Supabase Database:**\n    -   Log in to your Supabase project.\n    -   Go to the "SQL Editor" section.\n    -   Run the following SQL commands to create the `suggestions` table and related types/indexes:\n        ```sql\n        -- Create the ENUM type for suggestion status\n        CREATE TYPE suggestion_status AS ENUM ('PENDING', 'APPROVED');\n\n        -- Create the suggestions table\n        CREATE TABLE suggestions (\n            id UUID PRIMARY KEY DEFAULT gen_random_uuid(),\n            text TEXT NOT NULL,\n            status suggestion_status NOT NULL DEFAULT 'PENDING',\n            submitted_at TIMESTAMPTZ NOT NULL DEFAULT NOW()\n        );\n\n        -- Create an index for ordering by submission date\n        CREATE INDEX idx_suggestions_submitted_at ON suggestions(submitted_at DESC);\n\n        -- Create an index for filtering by status\n        CREATE INDEX idx_suggestions_status ON suggestions(status);\n        ```\n\n## Running the Application\n\n-   **Development mode (with hot-reloading using `nodemon`):**\n    ```bash\n    npm run dev\n    ```\n    The server will typically start on the port specified in your `.env` file (e.g., `http://localhost:3001`).\n\n-   **Production mode:**\n    ```bash\n    npm\ start\n    ```\n\n## API Endpoints\n\nAll endpoints are prefixed with `/api`.\n\n### Authentication (`/auth`)\n\n-   `POST /auth/login`\n    -   Authenticates the administrator.\n    -   **Body**: `{ "password": "admin_password_string" }`\n    -   **Returns**: `{ "token": "jwt_token_string" }` on success.\n\n-   `POST /auth/logout`\n    -   Logs out the administrator (client-side token invalidation).\n    -   **Returns**: `{ "message": "Logout successful." }`.\n\n### Suggestions (`/suggestions`)\n\n-   `GET /suggestions/public`\n    -   Returns a list of all suggestions with status `APPROVED`.\n    -   Sorted by `submittedAt` descending.\n\n-   `POST /suggestions`\n    -   Creates a new suggestion with status `PENDING`.\n    -   **Body**: `{ "text": "New idea for the application." }`\n    -   **Returns**: The created suggestion object.\n\n#### Admin Only (Requires JWT Authentication)\n\nThe following endpoints require a valid JWT in the `Authorization: Bearer <token>` header.\n\n-   `GET /suggestions/admin`\n    -   Returns a list of all suggestions (pending and approved).\n    -   Sorted by `submittedAt` descending.\n\n-   `PUT /suggestions/admin/:id/approve`\n    -   Changes the status of a suggestion from `PENDING` to `APPROVED`.\n    -   **Path Parameter**: `id` (UUID of the suggestion).\n    -   **Returns**: The updated suggestion object.\n\n-   `DELETE /suggestions/admin/:id`\n    -   Deletes a suggestion from the database.\n    -   **Path Parameter**: `id` (UUID of the suggestion).\n    -   **Returns**: Success message or 204 No Content.\n\n\n## Environment Variables\n\nA detailed list of environment variables used by this application:\n\n-   `PORT`: The port the server will listen on.\n-   `DATABASE_URL`: Full connection string for the Supabase (PostgreSQL) database.\n-   `ADMIN_PASSWORD`: The plain-text password for the admin user. This will be hashed by `bcryptjs` for comparison.\n-   `JWT_SECRET`: Secret key for signing and verifying JSON Web Tokens.\n-   `JWT_EXPIRES_IN`: Duration for JWT validity (e.g., "1h", "7d").\n-   `FRONTEND_URL`: The base URL of the frontend application, used for CORS policy.\n-   `NODE_ENV`: (Optional) Set to `development` or `production`. Influences some behaviors like debug logging.\n-   `DEBUG`: (Optional) Set to `true` to enable detailed debug messages from the logger.\n\n## Logging\n\nThe application uses a simple structured logger (`src/utils/logger.js`). Logs include timestamps, log levels, and contextual details. In a production environment like Render, these console logs are typically collected and can be viewed through the platform's logging interface.\n\n## Error Handling\n\nA global error handler and a utility function (`src/utils/errorHandler.js`) are used to provide consistent JSON error responses in the format:\n```json\n{\n  "message": "Error description",\n  "details": { /* Optional additional details */ }\n}\n```\n\n## Deployment\n\nRefer to the original specification document for deployment instructions to platforms like Render (backend) and Vercel (frontend). Ensure all necessary environment variables are configured on the deployment platform.\n\n---\n\nThis README provides a comprehensive guide to getting the backend server up and running.
